# Bastion 기획서

## 1. 개요
| 항목 | 내용 |
|---|---|
| 제목 | Bastion |
| 장르 | 2D 횡스크롤 소울라이크 액션 |
| 분위기 | 다크 판타지, 픽셀 아트 |
| 플랫폼 | PC |
| 엔진 | Unity 6, URP 2D |
| 분량 | 스테이지 1개 (5~10분) + 보스 1체 |
| 기간 | 4주, 주 6시간 (총 약 24시간) |
| 목적 | 포트폴리오 |

**핵심 목표**: 짧지만 완성도 높은 한 스테이지. 손맛(타격감), 보스 패턴 설계, 깔끔한 코드 구조를 보여주는 것.

## 2. 세계관
한때 왕국을 지키던 성채 **Bastion**이 저주에 잠식되었다. 성채를 지키던 수호자는 타락해 처형인이 되었고, 성채 안은 언데드와 괴물로 가득하다. 마지막 남은 기사가 맹세를 지키기 위해 성채로 들어간다.

- **주인공**: 이름 없는 기사
- **최종 보스**: 타락한 수호자 (Undead Executioner)
- **무대**: 성 외곽의 다리 → 무너진 성당 → 보스의 방

## 3. 핵심 게임 루프
```
탐색 → 전투 → 체크포인트 → 보스 → 클리어
         ↑         │
         └─ 사망 ──┘ (마지막 체크포인트에서 재시작)
```

## 4. 플레이어
| 동작 | 상세 |
|---|---|
| 이동 | 가감속이 있는 달리기 |
| 점프 (↑) | 가변 점프 높이, 코요테 타임, 점프 버퍼 |
| 더블점프 | 공중에서 1회 추가 점프 (높이 2.4), 착지 시 회복 |
| 구르기 (X) | 0.4초 구르기, 무적 0.32초, 쿨타임 0.3초, 공중 1회, 구르는 중에도 중력 적용 |
| 공격 | 3타 콤보 (Attack1 → Attack2 → Combo), 입력 버퍼 |
| 피격 | 경직, 넉백, 짧은 무적 시간 |
| 사망 | 사망 애니메이션 후 체크포인트에서 재시작 |

**타격감 연출**: 히트스톱, 카메라 쉐이크, 피격 플래시, 파티클

## 5. 적
| 이름 | 에셋 | 타입 | 행동 |
|---|---|---|---|
| Skeleton | Monsters Creatures Fantasy | 근접 | 순찰 → 추적 → 공격, 정면 공격을 방패로 방어 |
| Wizard | GothicVania Church | 원거리 | 거리 유지, 파이어볼 발사 |
| Flying Eye (선택) | Monsters Creatures Fantasy | 공중 | 비행하며 돌진 |

AI는 상태 머신으로 구현한다: `Idle / Patrol / Chase / Attack / Hit / Dead`

## 6. 보스: 타락한 수호자
| 패턴 | 에셋 애니메이션 | 내용 |
|---|---|---|
| 낫 베기 | attacking | 접근 후 근접 베기 |
| 스킬 | skill1 | 범위 공격, 예고 모션 있음 |
| 소환 | summon | 소환수를 불러냄 |

- **페이즈 1 (HP 100~50%)**: 패턴 간격이 길고 소환은 하지 않음
- **페이즈 2 (HP 50% 이하)**: 공격 속도 증가, 소환 패턴 추가
- 페이즈가 바뀔 때 연출을 넣는다 (idle2, 카메라 쉐이크)

## 7. 레벨 구성
1. **성 외곽 다리**: 조작 튜토리얼, Skeleton 1~2마리
2. **성당 내부**: 플랫폼 구간, Skeleton과 Wizard 조합, 체크포인트
3. **보스의 방**: 보스전

**타일 사용 규칙** (GothicVania Church 제작자 컨셉 `concepts.psd` 기준, 모든 지형의 윗면 각도를 바닥 덩어리에 통일)
| 요소 | 조각 | 사용법 |
|---|---|---|
| 땅 | 바닥 덩어리 3종 (0~10열, 10~12행) | 3칸 조각 경계에 맞춰 이어 붙임. 표면 → 거친 아랫단 → 어둠, 그 아래는 어둠 채움(1열 5행) |
| 높은 땅 | 바닥 덩어리 | 같은 덩어리를 높여 놓고 아래는 어둠 (원본 기둥은 윗면 두께가 달라 쓰지 않음) |
| 계단 | 바닥 덩어리 한 단 | 그 위를 경사 폴리곤 충돌이 덮음 |
| 떠 있는 발판 | 바닥 덩어리 윗면 + 파생 밑면 타일 | 밑면은 아래 가장자리와 이어진 어둠만 투명 처리. 흩어지는 돌 조각은 충돌 없는 `LevelDecor` |
| 양 끝 벽 | 파생 석재 블록 (원본 기둥 몸통 2×2칸을 바닥 팔레트로 교체) | 아래에서부터 2칸 단위로 쌓고 하나 걸러 좌우 뒤집음. 맨 아래 줄은 바닥 앞 모서리 높이에서 끝나고, 벽 뒤(`LevelUnder`)에 바닥 덩어리가 이어져 앞면과 거친 끝이 옆 바닥과 이어짐 |
| 벽 옆면 | 파생 타일 `WallSide_0/1/A/B` (`LevelFront`, 오른쪽 벽은 좌우 뒤집기) | 비스듬한 시점의 벽 안쪽 면. 아래 모서리는 바닥 앞 모서리에서 뒤 모서리(밝은 바닥 시작, 21px 위)까지 60°로 오르는 대각선, 줄눈도 같은 기울기 |
| 벽 옆·벽 밑 바닥 | 파생 조각 `FloorEdge` | 반쪽씩 조합(왼쪽: 1열 왼쪽 반+0열 오른쪽 반, 오른쪽: 2열 왼쪽 반+1열 오른쪽 반)해 같은 타일을 이어 깔아도 무늬가 이어짐. 벽 밑(`LevelUnder`)에도 깔아 앞 테두리와 돌 띠가 벽 밑까지 이어짐 |
| 맵 바깥 | 어둠 채움 | |
| 실내 천장 | 처마 조각 (3~4열, 2~3행) | 보스 아레나 위 띠 + 어둠 |
| 배경 | 벽돌 벽, 아치 창문, 촛대 벽 (10~19열, 1~4행) | 배경 타일맵 |

파생 타일은 원본 파일을 수정하지 않고 원본 픽셀과 색만으로 만들었다. 팔레트 교체 이유: 원본 기둥은 파란빛의 진한 보라, 바닥은 분홍빛 연보라라 밝기만 맞추면 채도가 튀었다.

**Stage1**: 시작(체크포인트) → 높은 땅 2개와 화염 분출구가 있는 구간(Skeleton) → 화염 구덩이 → 중간 구간(Skeleton, 높은 땅 위 Wizard, 높은 땅 옆 피스톤) → 계단 → 아레나 앞 체크포인트 → 보스 아레나(천장, 회피용 높은 땅, 진입 시 입구 봉쇄). 떠 있는 발판 6개(더블점프 경로).

## 7-1. 함정
| 함정 | 동작 | 위치 |
|---|---|---|
| 화염 분출구 | 분출구가 달아오르며 불티가 위로 뿜어짐(예고) → 불기둥(피해 20). 그림은 세로 0.75배로 바닥 윗면 두께에 맞춤 | 시작 구간 2, 구덩이 2(번갈아 작동), 중간 구간 2 |
| 벽 피스톤 | 준비(예고) → 돌출해 밀쳐냄(피해 12, 강한 넉백) | Wizard 기둥 왼쪽 면 |

- 가시 함정은 원본이 위에서 본 시점이라 바닥과 어울리지 않아 화염으로 통일했다.

- 모든 함정은 그림 프레임과 피해 판정이 같은 시간표로 움직이고, 한 번 작동할 때 한 번만 피해를 준다.
- 함정은 활성화된 시점부터 대기 상태로 시작한다.

## 7-2. 공격 예고
- Skeleton, Wizard: 공격 시작부터 판정 직전까지 무기(손) 주변으로 붉은 입자가 모인다.
- 보스: 공격 전 0.5초 예비 동작(2페이즈 0.35초) 동안 몸 주변으로 보라색 입자가 모인다.

## 9. 이펙트 (파티클)
Unity 기본 **Particle System**(Shuriken)으로 만든다. 픽셀 아트에 맞게 작은 사각형 스프라이트를 쓰고, Point 필터와 PPU 16을 적용한다.

| 분류 | 이펙트 | 발생 시점 | 우선순위 |
|---|---|---|---|
| 전투 | 타격 스파크 | 공격이 적중할 때 (히트스톱과 함께) | 필수 |
| 전투 | 피 / 뼛조각 | 적이 피격되거나 사망할 때 | 필수 |
| 전투 | 방패 막기 불꽃 | Skeleton이 정면 공격을 막을 때 | 필수 |
| 이동 | 먼지 | 착지, 대시, 달리기 방향 전환 | 필수 |
| 이동 | 대시 잔상 | 대시 중 | 선택 |
| 보스 | 예고 이펙트 | skill1 범위 공격 직전 | 필수 |
| 보스 | 소환 / 페이즈 전환 | summon, 페이즈 2 진입 | 선택 |
| 환경 | 먼지, 재, 촛불 | 성당 내부 배경 | 선택 |
| 기타 | 체크포인트 활성화 | 체크포인트 저장 시 | 선택 |

- 자주 생기는 이펙트(스파크, 먼지)는 **오브젝트 풀**로 재사용한다.
- 발생 시점은 애니메이션 이벤트나 전투 이벤트에서 `EffectManager`를 호출해 연결한다.
- 2D 조명을 받지 않도록 Unlit 머티리얼을 쓰고, Sorting Layer로 캐릭터 앞/뒤를 정한다.

## 10. 기술 설계
| 항목 | 방식 |
|---|---|
| 상태 관리 | 플레이어, 적, 보스가 공통 FSM 구조를 재사용 |
| 데이터 | 공격력, 체력, 패턴 수치를 ScriptableObject로 관리 |
| 입력 | New Input System |
| 물리 | Rigidbody2D 기반 커스텀 컨트롤러 |
| 카메라 | Cinemachine 2D |
| 전투 | `IDamageable` / `Health`, 판정 구간에 `OverlapBox` 질의 |
| 연출 타이밍 | `AttackStep` 시간표(판정 시작/끝, 캔슬 시점)를 코드가 관리. 애니메이션 이벤트에 의존하지 않아 테스트 가능 |
| 레벨 충돌 | 그림 타일맵과 충돌 타일맵 분리. 충돌은 각 기둥의 맨 윗칸을 빼고 깔아서 캐릭터가 바닥 그림의 윗면 안쪽을 밟음 |
| 레벨 편집 | Church Tile Palette로 Level 타일맵을 칠하면 Collision 타일맵이 자동으로 다시 만들어짐 (Tilemap 변경 콜백). 경사로는 별도 폴리곤 충돌 |
| 경사 | 지상에서는 중력을 누적하지 않고 바닥에 붙임 (가만히 있으면 미끄러지지 않음) |
| 검증 | PlayMode 테스트 (InputTestFixture로 입력 재현) |
| 이펙트 | Particle System + 오브젝트 풀 (9장 참고) |
| 에셋 임포트 | `PixelSpriteImporter` (PPU 16, Point, 자동 슬라이스) |
